# 自动同步上游

`Sync upstream` 每小时检查一次 `liyangpengs/qq-farm-bot` 的 master，也可以从 GitHub Actions 页面手动运行。修改同步工作流、脚本或前后端测试时会立即运行一次，便于修复阻塞测试后马上验证同步。GitHub 定时任务可能排队延迟。

有更新时合并上游，保留 Fork 自己的第三方登录（应用宝 / PCMgr）、重连功能和简介截图；随后运行后端测试、前端类型检查与测试，以及完整构建。全部成功后，独立发布任务才把已验证的合并提交推送至 master。无更新时跳过安装与构建。

仅 README 顶部已知的 Fork 简介冲突会自动保留本 Fork 文案，其他文档及代码冲突都会停止。合并失败、测试失败，或测试期间 master 被其他提交更新时，均不会覆盖主分支。失败结果可在 Actions 中查看；解决问题后可重新运行。

验证任务只有仓库读取权限；仅发布任务持有写入权限，不使用额外的个人访问令牌，也不强制推送。自动同步更新的是 GitHub 仓库，不会重启或部署服务器。

## 版本更新与回归验证

2026-11-19 购买数量回归修复：跟随上游精确整数计算与禁止购买规则，余额不足、售罄、余额或单价未确认时最大购买数量为 0；测试不再要求强制抬高到 1。新增大于 JavaScript 安全整数范围的金额边界与恰好可购一份的验证。前端测试的改动也会立即触发同步检查。

2026-11-16 同步修复：小红花协议回归使用当前 `agreement` 字段，同时保留原始字节断言；邮箱调度模拟补齐牧场调度依赖；登录和连接测试保留真实工具函数，只覆盖被测时钟、日志等依赖。奶茶模拟提供兑换商店独立开放时段，验证结算期可制作和兑换、奶茶结束后商店仍可开放，以及各自结束边界禁止写入。

同步脚本的真实 Git 回归连续模拟两次上游更新，检查 Fork 功能和简介保留、合并后无更新时不重复提交、验证包可恢复发布、预期主分支不匹配时拒绝覆盖，以及代码冲突后回滚并保持工作区干净。上述检查验证同步机制，不能替代未来上游更新后的全量测试；遇到新的真实冲突或回归仍会停止发布。

游戏默认版本和证据时间由上游发布配置维护，测试校验版本格式、真实日期、有效时间戳以及 QQ / 微信独立选择和自定义覆盖行为，不再把当前版本号或发布时间写死在测试里。

当前 QQ / 微信 WASM 均核对各自发布清单的 SHA-256、有效 WASM 格式和实际初始化行为，并验证加解密往返。损坏二进制必须被运行时拒绝，不能为了同步成功跳过完整性校验。

逐字节的 QQ 宿主回归样例绑定在 `core/tests/fixtures/qq-host-20261101.json` 与配套历史 WASM 上。该样例来自仓库提交 `3090f579ffc9a90367597e4039857068ff182650`，使用合成账号标识；通过隔离测试模块让当前宿主执行历史二进制，仅替换历史版本元数据与资源路径。升级当前 WASM 不需要重新生成这个固定答案，宿主行为改变仍会触发回归失败。

GitHub 页面上的 Sync fork 按钮只使用 GitHub 通用合并逻辑，不执行本仓库的 README 处理与测试流程。遇到它显示文档冲突时，先查看 Actions 的 Sync upstream 运行结果。领先上游的提交是 Fork 自有功能，不能使用 Discard commits 来消除提示。出现真实代码冲突、WASM 接口变化或功能回归时，仍需人工处理；自动同步不能保证所有未来改动都可无人干预地合并。


## 2026-11-25 会话宿主兼容修复

合并上游独立会话宿主时，同时保留第三方授权与异步账号控制：手动停止会取消自动续期，重启会恢复续期，已有会话 ID 会传给工作进程，后端分离时停止本实例的续期调度。第三方账号的超时恢复标记会传给实际持有连接的网关工作线程，普通账号不启用。
